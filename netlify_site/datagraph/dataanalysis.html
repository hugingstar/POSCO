📊 데이터 통계 분석 및 전처리 리포트

1. 머신러닝 데이터 전처리

머신러닝 모델의 성능은 데이터의 질에 의해 좌우됩니다. 아무리 뛰어난 알고리즘도 쓰레기 데이터(Garbage)가 들어가면 쓰레기 결과(Garbage)를 내놓습니다. (Garbage In, Garbage Out)

1.1. 데이터 로드 관련 개념

데이터 분석을 시작하기 위해서는 원시(Raw) 데이터를 메모리에 올리는 과정이 필요합니다. 텍스트 파일(CSV 등)을 로드할 때 가장 흔히 겪는 문제는 바로 문자열 인코딩(Encoding)입니다.

💡 한글 인코딩 깨짐 방지 팁

  • cp949 / euc-kr: 과거 윈도우나 한국의 오래된 엑셀 시스템에서 자주 사용하던 방식입니다. 데이터를 불러왔을 때 한글이 처럼 깨진다면 encoding='cp949'를 시도해 보세요.
  • utf-8: 웹과 현대 프로그래밍의 글로벌 표준입니다. 가급적 모든 데이터는 UTF-8로 다루는 것이 정신 건강에 좋습니다.
  • utf-8-sig: 엑셀(Excel)에서 UTF-8 CSV 파일을 열었을 때 한글이 깨지는 것을 막기 위해 파일 맨 앞에 BOM(Byte Order Mark)을 추가한 포맷입니다. 데이터를 저장하거나 불러올 때 encoding='utf-8-sig'를 사용하면 파이썬과 엑셀 양쪽에서 완벽하게 호환됩니다.

2. 데이터 분석 및 시각화

2.1. 데이터 통계 분석 (Describe)

데이터를 로드한 직후 가장 먼저 해야 할 일은 데이터의 기초 통계량(평균, 편차, 최솟값, 최댓값, 사분위수 등)을 확인하는 것입니다. 아래는 불러온 데이터의 요약 통계표입니다.

💡 통계 분석(Describe)을 왜 해야 할까요?

  • Count가 매칭되지 않는 상황: 위 표에서 count 값이 다른 컬럼에 비해 적은 컬럼이 있다면, 결측치(Missing Value)가 숨어있다는 뜻입니다. 즉시 보간이나 제거 계획을 세워야 합니다.
  • Min / Max 의 극단성: min이나 max 값이 평균(Mean)이나 3사분위수(75%)와 상식 밖의 차이를 보인다면 이상치(Outlier)가 존재함을 시사합니다.
  • Mean 과 Median 의 차이: 평균과 50%(중앙값)의 차이가 크다면, 데이터가 정규분포를 따르지 않고 한쪽으로 꼬리가 길게 늘어진 비대칭 분포(Skewed)를 가짐을 의미합니다.

2.2. 데이터 결측치 처리 (Missing Value Interpolation)

결측치를 처리하는 방법은 단순히 행을 지우거나 평균으로 채우는 것부터, 시계열 트렌드에 맞춰 다항식으로 보간하는 방법까지 다양합니다. 아래 차트에서 각 방식의 곡선 차이를 확인해 보세요.

💡 결측치 보간 기법 선택 시 조심해야 할 것들

  • 평균/중앙값 대체: 매우 안전하고 쉽지만, 시계열 데이터의 트렌드(상승/하락 흐름)를 완전히 파괴하여 직진하는 수평선을 만듭니다.
  • 선형 보간 (Linear Interpolation): 오직 '수분율' 자체의 시간 흐름만 봅니다. 결측치 발생 직전과 직후의 수분율을 단순히 1차원적인 직선으로 잇습니다. 만약 그 사이에 '소성온도'가 급변하여 수분율이 요동쳤어야 하는 물리적 상황이라도 이를 무시하고 지나가 버립니다.
  • 선형회귀 보간 (Regression Imputation): 시간이 아닌 변수 간의 인과관계를 활용합니다. 정상 구간에서 "소성온도가 변할 때 수분율이 얼마나 변하는지" 수학적 패턴을 학습한 뒤, 결측 구간의 '소성온도' 값을 대입하여 수분율을 추정합니다. 공정의 물리적 특성을 가장 잘 반영하지만, 현실의 미세한 노이즈를 무시하고 기계적인 1차 방정식 선 위에만 값을 올려버리는 단점이 있습니다.
  • 2차 회귀 보간 (Quadratic Regression): '소성온도'와 '수분율'의 관계가 단순한 직선이 아니라 포물선(가속/감속) 형태를 띤다고 가정합니다. 온도가 일정 수준을 넘어가면 수분율 증발이 둔화되거나 가속화되는 비선형적인 물리 현상을 반영할 수 있습니다.
  • 3차 회귀 보간 (Cubic Regression): 소성온도에 따른 수분율 변화가 S자 곡선처럼 복잡한 굴곡을 가질 때 사용합니다. 주의점(과적합): 차수가 높아질수록 주어진 정상 데이터에는 완벽하게 들어맞지만, 소성온도가 조금만 새로운 값을 가져도 수분율 예측값이 우주로 솟구치거나 지하로 꺼지는 치명적인 과적합(Overfitting) 현상이 발생할 수 있습니다.

2.3. 데이터 이상치 탐지 (Outlier)

통계적 이상치를 찾아내기 위해 주로 사분위수를 이용한 IQR(Interquartile Range) 기법을 사용합니다. 아래는 이상치를 제거하기 전(Before)과 후(After)의 분포 변화입니다.

💡 이상치를 함부로 지우면 안 되는 상황

  • 단순히 IQR 바깥에 있다고 무작정 삭제하면 치명적인 정보를 잃을 수 있습니다.
  • 센서 오작동(Error) vs 진짜 불량(Defect): 센서가 고장나서 순간적으로 -9999 가 찍힌 것이라면 지워야 하지만, 실제 설비가 과열되어 1000도가 찍힌 것이라면 불량을 예측하기 위한 가장 핵심적인 데이터이므로 절대 지우면 안 됩니다.
  • 이상치를 제거하기 전에는 도메인 전문가(현장 엔지니어)와 이 수치가 물리적으로 발생 가능한 수치인지 논의하는 과정이 필수적입니다.

2.4. 원핫 인코딩 (One-Hot Encoding) & 데이터 추가

머신러닝 모델은 문자열을 이해하지 못합니다. 설비호기 (A, B, C)와 같은 범주형 데이터를 컴퓨터가 이해할 수 있도록 0과 1의 벡터로 풀어쓰는 과정이 원핫 인코딩입니다.

C001

💡 데이터가 너무 늘어나는 문제점 (차원의 저주) 및 대안

  • 제품의 개별 LOT 번호나 수백 명의 작업자 사번처럼 범주(Category)의 종류가 수백, 수천 개에 달할 경우 원핫 인코딩을 하면 컬럼이 수천 개로 늘어납니다.
  • 컬럼이 과도하게 많아지면 모델이 패턴을 찾지 못하는 차원의 저주(Curse of Dimensionality) 현상이 발생하며, 대부분이 0으로 채워진 희소 행렬(Sparse Matrix) 때문에 메모리가 폭발합니다. 이럴 땐 원핫 인코딩 대신 아래의 대안을 고려해야 합니다.
  • Label Encoding (라벨 인코딩): 카테고리를 A=1, B=2, C=3 처럼 단순히 임의의 정수로 매핑합니다. 차원은 늘어나지 않지만, 모델이 1과 3 사이의 수치적 크기 차이를 서열이나 가중치로 오해할 수 있는 단점이 있습니다.
  • Target Encoding (타겟 인코딩): 해당 범주가 가지는 '타겟(정답)'의 평균값으로 문자를 치환합니다. (예: A설비에서 생산된 제품들의 평균 불량률이 0.15라면 A를 0.15로 치환)
  • Embedding (임베딩): 범주형 데이터를 딥러닝 신경망을 통해 의미를 가지는 조밀한(Dense) 실수 벡터 공간에 배치하는 고급 기법입니다. 수만 개의 단어를 다루는 자연어 처리(NLP)나 추천 시스템에서 필수적으로 쓰입니다.

2.5. 최종 데이터 통계 분석 (Cleaned 전처리 완료 데이터)

2.6. 데이터 상관관계 (Correlation)

변수들끼리 얼마나 서로 관련이 있는지(하나가 증가할 때 다른 하나도 증가하는지) 파악하는 히트맵입니다.

💡 상관계수 알고리즘 선택 기준 및 수치 해석 팁

  • Pearson (피어슨): 가장 널리 쓰이며, 두 변수가 선형적(직선) 비례 관계일 때 사용합니다. 정규분포를 따를 때 가장 정확합니다.
  • Spearman (스피어만): 값의 크기 자체가 아니라 순위(Rank)를 매겨 상관관계를 구합니다. 비선형적인 관계나 이상치가 많을 때 적합합니다.
  • Kendall's tau (켄달 타우): 스피어만과 비슷하게 순위 기반이지만, 데이터 샘플 크기가 매우 작거나 중복된 값(동률)이 많을 때 통계적으로 더 신뢰할 수 있습니다.
  • [수치 해석 가이드 (절댓값 기준)]
  • 0.7 ~ 1.0 (강한 상관관계): 두 변수가 매우 강하게 묶여 있습니다. (예: 0.85가 나왔다면, A가 증가할 때 B도 무조건 강하게 비례해서 증가함을 뜻합니다.)
  • 0.4 ~ 0.7 (중간 상관관계): 뚜렷한 경향성이 존재합니다. 머신러닝 예측 모델에서 유의미한 핵심 변수(Feature)로 자주 선택됩니다. (예: 0.55가 나왔다면 추세가 분명히 보입니다.)
  • 0.0 ~ 0.3 (약한/없는 상관관계): 거의 관계가 없습니다. (예: 0.12가 나왔다면, A와 B는 완전 독립적으로 무작위로 움직인다고 봐야 합니다.)

2.7. 데이터 인과관계 (Causality in Time Series)

상관관계가 높다고 해서 반드시 원인과 결과(인과관계)인 것은 아닙니다. 예를 들어 여름에 아이스크림 판매량과 익사 사고율은 상관관계가 높지만(둘 다 기온 때문에 발생), 아이스크림이 익사를 유발하는 것은 아닙니다.

💡 시계열 공정 데이터의 변수 구분 가이드

  • 타겟 변수 (Target, Y): 우리가 최종적으로 예측하거나 맞추고 싶은 결과입니다. (예: 양품여부, 방전용량)
  • 제어 변수 (Control, X): 작업자나 시스템이 의도적으로 값을 조작하고 설정할 수 있는 변수입니다. 타겟을 원하는 방향으로 바꾸기 위해 조절합니다. (예: 소성온도 세팅값, 소성시간)
  • 입력 변수 (Input / Sensor, X): 조작할 수는 없지만 공정 중에 자연스럽게 관측되거나 원재료에서 발생하여 결과에 영향을 미치는 변수입니다. (예: 원재료의 입도, 측정된 수분율)

2.8. 추가 검토: 시계열 데이터 특이성

시간의 흐름에 따라 기록되는 시계열 데이터는 일반적인 테이블 데이터와 달리 시간축(Time Index) 자체의 무결성이 매우 중요합니다.

💡 시계열 데이터 전처리 시 필수 검토 사항

  • Time index 문제: 데이터 수집 주기가 불규칙하거나 중간에 누락된 초/분/시간이 없는지(Resampling 필요) 검토해야 합니다.
  • 시간 지연 검토 (Time Lag): 온도를 올렸다고 즉시 수분율이 변하지 않습니다. 설비 특성상 10분 뒤에 수분이 증발한다면, 현재 온도는 10분 뒤의 수분율과 짝지어(Shift) 분석해야 인과관계가 맞습니다.
  • 시계열 데이터 인덱스 비매칭: 서로 다른 센서 A(1초 주기)와 센서 B(5초 주기)의 데이터 병합 시 타임스탬프가 엇갈립니다. 이럴 땐 Nearest, Forward Fill 등 적절한 정렬(Alignment) 기법을 고민해야 합니다.
