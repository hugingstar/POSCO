🦜 파이썬 클래스 (Class)

1. 클래스 구조 (Class Structure)

"자주 사용하는 변수들과 함수(메소드)들을 하나의 커다란 설계도(틀)로 묶어놓은 것을 클래스라고 합니다! 흔히 붕어빵 틀에 비유합니다."

  • 클래스(Class): 붕어빵 틀 (설계도)
  • 객체/인스턴스(Object): 틀에서 찍어낸 실제 붕어빵 (결과물)

2. 메소드 (Methods)와 생성자 (__init__)

클래스 안에 들어있는 함수를 메소드라고 부릅니다. 클래스가 만들어질 때 가장 먼저 자동으로 실행되는 특별한 메소드가 바로 생성자(__init__)입니다.

  • self: 자기 자신을 가리키는 파라미터입니다. 클래스 내부의 변수나 다른 메소드를 부를 때 꼭 붙여줘야 합니다!
class Bird:
    def __init__(self, name: str):
        # 생성자: 새가 태어날 때 이름을 정해줍니다.
        self.name = name

    def speak(self) -> None:
        # 일반 메소드
        print(f"{self.name}가 짹짹 운다!")

# 클래스로 객체 만들기
my_bird = Bird("참새")
my_bird.speak() # 참새가 짹짹 운다!

3. 상속 (Inheritance)

이미 만들어둔 붕어빵 틀(부모 클래스)의 모든 기능을 그대로 물려받고, 거기에 새로운 기능만 살짝 추가해서 새로운 틀(자식 클래스)을 만드는 기능입니다!

# Bird 클래스를 상속받는 껄무새 클래스 만들기
class Parrot(Bird):
    def mimic(self, word: str) -> None:
        # 부모(Bird)에 없던 새로운 메소드 추가!
        print(f"{self.name}가 사람 말을 따라합니다: '{word}'")

# 객체 만들기
my_parrot = Parrot("껄무새")
my_parrot.speak() # 부모 클래스의 기능을 그대로 사용!
my_parrot.mimic("파이썬 최고") # 자신만의 기능도 사용!

4. 🏗️ 포스코퓨처엠 실무: 클래스를 활용한 아키텍처(Architecture) 설계

파이썬 클래스는 단순한 코드 묶음을 넘어, 복잡한 시스템을 체계적으로 설계(Architecture)하는 데 필수적인 역할을 합니다. 포스코퓨처엠의 각 부서에서 클래스를 어떻게 활용하는지 살펴볼까요?

  • [안전보건기획그룹] 센서 통합 관리 아키텍처: 현장의 유해가스 센서, 온도 센서, 스마트워치 등 다양한 장비들은 각각 통신 방식이 다릅니다. 최상위 부모 클래스인 Sensor를 만들고, 이를 상속받는 GasSensor, BioSensor 자식 클래스들을 구현하면(상속), 수백 개의 장비 제어 코드를 하나의 통일된 구조로 깔끔하게 관리할 수 있습니다.
  • [실리콘음극재개발그룹] R&D 테스트 장비 인터페이스: 배터리 Full Cell 충방전 테스터기마다 데이터 출력 포맷이 다를 때, BaseTester라는 표준 클래스를 정의합니다. 이후 새로운 장비가 도입되더라도 기존 분석 코드를 수정할 필요 없이, BaseTester를 상속받은 새 클래스만 추가하면 되어 유지보수성이 극대화됩니다(다형성).
  • [내화물정비섹션] 예지보전(PdM) 모델 객체화: 수많은 내화물 설비의 노후화를 예측할 때, 설비 하나하나를 Equipment라는 객체(Instance)로 생성합니다. 각 객체가 스스로의 현재 온도, 가동 시간, 균열 상태 등을 변수(상태)로 기억하고, predict_failure() 메소드를 통해 자체적으로 고장 시점을 계산하게 설계하면 관리가 매우 직관적입니다.
  • [DX추진반] 모듈형 RPA 봇 설계: 엑셀 취합, ERP 데이터 다운로드, 메일 발송 등 자주 쓰이는 자동화 기능들을 독립적인 클래스(모듈)로 분리합니다. 현업 부서에서는 블록 장난감을 조립하듯 이 클래스들을 불러와 원하는 RPA 봇을 빠르고 안전하게 찍어낼 수 있습니다.
💡 실무 팁: 처음부터 클래스를 완벽하게 설계하려고 하지 마세요!
현업에서는 요구사항이 계속 바뀝니다. 처음에는 간단한 함수들로 스크립트를 짜다가, 코드가 길어지고 비슷한 변수들이 계속 묶여 다닐 때 "아, 이걸 클래스로 묶으면 편하겠구나!" 하는 시점에 리팩토링(Refactoring)하는 것이 가장 실용적인 접근입니다.
